# Status on 2026-10-13 (work paused)

Work on the port is paused. This file records where it stands so it can be picked up again.

## Device results (RG35XX H, intro and attract, 150 s runs)

| Build | Intro movie fps | Static screens fps |
|---|---|---|
| Rebased handheld build (`dist/mscharged.zip`) | 6 to 8.5 | |
| plus `aurora-gpu` 0007 and the audio fix | 8.4 to 9.9 | |
| plus `aurora-gpu` 0008 (no submit sync) | 11.5 to 17.8 | |
| plus `aurora-gpu` 0009 (VI pass merge) | 13 to 20 | 30 |

`[gl-time]` with 0009 (ms per second): ops 471, parse 103, slot-wait 251, fence-wait 426, present 34. The render worker waits on the GPU (fence-wait), so the Mali does too much work per frame even for a plain movie. Finding out what (draws, passes, copies per movie frame) is the next step; `aurora-gpu` 0010 and 0011 add the timers and pass logs for that (`AURORA_GL_PASSLOG`, `AURORA_GL_PASSTIME`), not yet measured on the device.

Audio: the AX queue stays full in the intro (underruns only at startup and one loading point). Movie audio has its own counters since `port-perf` 0004 (not yet measured on the device). The user still hears stutter in the intro movie; the likely cause is the movie running at 13 to 20 fps instead of its own rate.
